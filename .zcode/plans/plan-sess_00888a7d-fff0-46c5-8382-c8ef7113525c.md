## 实现方案

1. 修改 `entry/src/main/ets/pages/ConfigConverter.ets` 的导入名称初始化逻辑：
   - 配置内容包含 Access Server 的 `PROFILE` / `FRIENDLY_NAME` 时，继续优先使用配置内名称。
   - 普通本地 `.ovpn` / `.conf` 文件没有内置名称时，使用传入的原始文件名，并仅移除末尾的 `.ovpn` 或 `.conf` 扩展名（大小写不敏感）。例如 `office.ovpn` 默认命名为 `office`，`vpn.prod.conf` 默认命名为 `vpn.prod`。
   - 云端导入的 `fileName` 为空时，继续回退到现有的“转换的配置文件”。

2. 继续复用现有 `uniqueName()` 处理重名，不改变当前规则。例如已有 `office` 时，新导入项默认命名为 `office 1`。

3. 保留完整文件名用于导入日志，不修改 `FileUtil`、文件选择器、资源字符串或后续名称编辑流程；这样日志仍显示 `office.ovpn`，只有配置名称使用去扩展名后的文件名。

4. 运行项目现有的 Hvigor `assembleHap` 构建验证 ArkTS 编译。当前项目没有可复用的 ArkTS 单元测试基础设施，因此不为这项单一字符串逻辑额外引入测试框架。

预计只修改一个文件：`entry/src/main/ets/pages/ConfigConverter.ets`，不会触碰工作区中已有的其他未提交改动。
