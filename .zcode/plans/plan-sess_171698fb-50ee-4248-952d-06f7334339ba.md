## 目标与总体决策

在不改变现有 OpenVPN 使用方式和视觉语言的前提下，将 FRP 做成首页与 OpenVPN 并列的一级功能。按 `_ref/frp-Android` 的产品行为，首期将配置类型建模为 `frpc` 与 `frps` 两类；如果产品最终只需要 frpc，可在不改变整体架构的情况下关闭/移除 frps 模板和运行入口。

核心技术路线选择：

- UI：在现有 `Index` 页面中增加一级 `OpenVPN / FRP` 切换，不把 FRP 藏到设置或 OpenVPN 配置页内。
- 配置：配置原文以 TOML 文件为事实来源，同时维护稳定 ID、显示名、自启动和最近运行信息；支持导入、新建空白配置、新建模板配置、编辑、复制、重命名、导出、删除。
- 运行：新增独立 `FrpServiceAbility`，每份配置对应一个独立运行实例，允许多个 frpc/frps 并行；不复用 `VpnServiceAbility`、`OvpnEngine`、TUN 和 `libovpnexec.so` 的全局状态。
- Native：优先采用 HarmonyOS Native Child Process API，由独立的 FRP host 动态库承载 `Main(NativeChildProcess_Args)`；不直接照搬 Android 的 `ProcessBuilder` 或 `GOOS=android` 二进制。
- 可靠性：先完成 Native Child Process 与 FRP 核心的 arm64 真机 smoke test，再接入完整启停 UI；若平台不允许运行该核心，不提交带有假启动状态的产品页面。

## 一、产品与 UI 设计

### 1. 首页一级信息架构

修改 `entry/src/main/ets/pages/Index.ets`，保留现有主色工具栏和 OpenVPN 列表，在工具栏下增加轻量的一级切换控件：

- `OpenVPN`：继续渲染现有 `ProfilesTab`，保持现有导入、流量、日志、关于入口和交互不变。
- `FRP`：渲染新增 `FrpHome`，拥有独立的配置列表、状态和 FAB。
- 切换状态只属于当前页面，不改变 OpenVPN 的路由和连接状态。
- 工具栏图标按当前上下文显示：FRP 页面显示 FRP 导入、日志/运行概览、设置或关于入口；不增加新的视觉体系。

沿用 `Theme.ets` 的 `PRIMARY`、`ACCENT`、`WINDOW_BG`、`CARD_BG`、状态色、56 高 toolbar 和 12 圆角卡片，不修改现有 OpenVPN 颜色以免回归。

### 2. FRP 配置列表

新增 `components/tabs/FrpTab.ets` 或 `pages/FrpHome.ets`，布局与 `ProfilesTab` 对齐：

- 空状态：说明可导入 TOML 或新建配置，提供主操作按钮。
- 分组：`frpc`、`frps` 两个小节；没有对应配置时不显示空分组。
- 配置卡片：左侧 Switch，中部显示显示名、类型、文件名/服务器概要、状态徽章和最近错误摘要，右侧提供编辑入口；展开后显示最近日志和清除日志操作。
- 状态至少包含 `已停止`、`启动中`、`运行中`、`停止中`、`异常退出`、`启动失败`，颜色沿用现有连接状态色，不仅用一个布尔 running 标志。
- 运行时禁止编辑、重命名和删除，避免配置文件被进程读取期间发生竞态；停止后恢复操作。
- 右下角使用现有 56x56 FAB 规范，主操作为“新建配置”。
- 长日志不直接撑高卡片，使用可折叠区域并限制显示行数，进入详情页可看完整最近日志。

### 3. 导入、新建和编辑流程

新增 FRP 专用对话框/页面，优先复用 `ImportSourceDialog`、`InputDialog`、`ConfirmDialog`、`PrefRows` 和暗色编辑卡片样式。

**导入：**

- 使用 HarmonyOS Document Picker 选择 `.toml`，复制到应用私有的 `filesDir/frpc` 或 `filesDir/frps`；类型由用户确认或从配置入口确定，不信任文件名推断。
- 导入前校验扩展名、文件名、大小和 TOML 语法；重名自动给出可编辑的新名称。
- 导入完成后打开编辑页，并明确显示“配置尚未运行”。

**新建：**

1. 选择 `frpc` 或 `frps`。
2. 选择“从模板创建”或“空白配置”。
3. 模板页按参考项目提供中文优先、英文回退的模板卡片；首批覆盖 TCP SSH、STCP proxy/visitor、XTCP proxy/visitor、TLS frpc，以及基础/TLS frps。
4. 空白配置进入原文编辑器，不强制用户先填固定字段；编辑器提供常用块插入/字段提示，但不把 FRP 字段硬编码成会随版本失效的完整 schema。

**编辑页：**

- 新增 `pages/FrpConfigEdit.ets`，采用现有深色 `VPNPreferences/ProfileEdit` 的卡片、输入和 toolbar 风格。
- 顶栏显示返回、类型徽章、保存；底部或菜单提供“验证”“复制”“导出”“删除”。
- 主体为等宽字体多行 TOML 编辑区，同时提供文件名/显示名、自启动开关和最近一次验证结果。
- 保存使用临时文件 + 原子替换，保存前验证；保存失败保留原文件并明确提示。
- 支持配置复制：生成安全且不冲突的新文件名，复制正文但不复制运行状态和日志；复制后的配置默认停止。
- 重命名只允许 `[A-Za-z0-9._-]+.toml`，拒绝空名、路径分隔符、`..`、控制字符和超长名称。
- 导出单份配置使用系统文件选择器；另提供 FRP 配置/设置备份能力，但导出前提示 TOML 可能含 token、secretKey、私钥路径等敏感信息。

### 4. 日志与运行详情

新增 `pages/FrpLog.ets` 或配置详情内的日志页：

- 显示启动时间、实际状态、退出码、最近错误和最近日志。
- 日志支持选择复制、清除、按配置查看；默认限制最近行数/字节数，避免无限增长。
- 不记录完整 token、secretKey、密码或认证响应；对已知敏感字段和错误输出做最小脱敏。
- 通知/后台状态只作为运行提示，不把通知存在误认为进程一定存活；页面恢复时从服务状态快照和真实运行状态重建。


## 三、FRP 服务和进程架构

新增：

- `entry/src/main/ets/frp/FrpController.ets`
- `entry/src/main/ets/frp/FrpRuntimeAdapter.ets`
- `entry/src/main/ets/frpservice/FrpServiceAbility.ets`
- `entry/src/main/ets/frpservice/FrpServiceProtocol.ets`

职责划分：

- `FrpController`：UI 发出 start/stop/stopAll/restart、查询状态/日志/版本；使用 Want + app 私有请求文件桥接，参考现有 `VpnController` 的耐受 Want 参数丢失设计，但不复制 VPN 专用字段。
- `FrpServiceAbility`：独立托管多配置运行实例，处理 `onCreate/onRequest/onDestroy`，为每个 config ID 建立唯一进程记录，序列化启停命令，更新状态快照和通知。
- `FrpRuntimeAdapter`：隔离具体的 HarmonyOS 进程 API，以便未来替换 Go/C++ FRP 核心而不改 UI 和领域层。
- `FrpLogStore/FrpStatus`：服务侧是 writer，UI 侧只读快照/监听，避免两个 Ability 同时写同一状态文件。

进程生命周期要求：

- 同一 `(type, configId)` 不允许重复启动。
- 启动成功、正常退出、异常退出、启动失败都必须回调服务并清理运行表。
- stop 必须等待/确认 child process 退出，必要时调用官方 kill API；不能只切换 UI 开关。
- service 销毁时遍历所有子进程并终止，清理运行状态但保留配置和历史日志。
- 支持多个 frpc/frps 并行，单个实例异常不影响其他实例和 OpenVPN。
- 进程参数使用绝对的私有配置路径或受控工作目录，禁止把用户输入直接拼为 shell 命令。
- child process 的 `isolationMode` 必须验证为可访问网络的模式；若开启隔离会导致 FRP 无法联网，不能默认使用。

## 四、Native FRP 核心与构建闸门

这是实现中最重要的前置阶段。当前仓库只有 Android 参考脚本，没有 OHOS FRP 源码/二进制；参考脚本的 `GOOS=android` 产物不能直接放进 HarmonyOS HAP。

### Phase 0：Native Child Process smoke test（先做）

新增一个最小的、非 FRP 的 native child host，验证目标 arm64 真机能够：

- 加载 `libfrp_host.so:Main` 形式的入口。
- 接收 `entryParams` 和传入 fd。
- 返回 child PID/句柄并持续运行。
- 通过 stdout/stderr 或 fd 回传一行状态。
- 正常退出、异常退出和 `OH_Ability_KillChildProcess` 都能被服务侧观察。
- HAP 签名安装后仍能加载动态库，并在应用沙箱中访问配置目录。

只有这个 smoke test 通过，才继续接入真实 FRP。

### Phase 1：FRP 核心适配

新增/修改：

- `native/third_party/frp/`：锁定一个明确的 FRP upstream revision，不复制 Android APK 产物。
- `native/frp/`：OHOS 构建脚本、host wrapper、日志/停止适配。
- `native/scripts/build-frpc-ohos.sh`（或等价 Windows/CI 脚本）：使用 DevEco OpenHarmony clang 和实际可用的 FRP/Go 构建方式。
- `entry/src/main/cpp/frp_host.cpp`、必要的 `frp_host.h`。
- `entry/src/main/cpp/frp_napi.cpp`（仅当 ArkTS 需要通过 NAPI 包装启动/状态/日志时）。
- `entry/src/main/cpp/types/libfrpbridge/index.d.ts`。
- `entry/src/main/cpp/CMakeLists.txt`：新增独立 `frpbridge/frp_host` target；不把 FRP 代码和全局状态塞入 `ovpnexec`。
- `entry/build-profile.json5`：仅在新增 ABI 且对应 FRP/OpenSSL 依赖齐全时扩展；首期保持 arm64，避免出现“应用能装但 FRP 没有该 ABI”的假支持。

适配要求：

- 如果 upstream Go FRP 不能直接以 OHOS 目标生成 child host，则先做一个明确的 C ABI/host 层；不能把 `cmd/frpc` 的 `main` 函数直接当作共享库 API。
- FRPC/FRPS 运行参数、配置根目录、日志 fd、停止信号、退出码都通过 `FrpRuntimeAdapter` 抽象。
- 不使用 Android `nativeLibraryDir`、`ProcessBuilder`、前台 Service 或 Android NDK 产物的假设。
- 编译产物和依赖在 HAP 中可检查，禁止把外部未验证二进制直接提交为可运行核心。

### Phase 2：FRP runtime smoke test

在真实 FRP 接入后，先不接完整 UI，使用最小服务命令验证：

- `frpc/frps` 版本读取。
- 有效 TOML 能启动并持续运行。
- 无效 TOML 能在启动前或短时间内返回错误和退出码。
- stdout/stderr 能进入 `FrpLogStore`。
- 正常停止和异常退出都能更新 `FrpStatus`。
- token/TLS/相对证书路径/本地监听端口可用。
- 同时启动两个配置时互不干扰。

## 六、外部能力的取舍

首期只实现用户已明确需要且能在 HarmonyOS 内稳定验证的能力：

- 应用内导入/新建/编辑/复制/重命名/导出/删除。
- 单配置和全部配置启停。
- 多配置并行。
- 配置级状态、日志、验证和后台通知。
- 配置级自启动开关（在平台允许的生命周期范围内）。

不直接照搬 Android 特有能力：

- `ContentProvider`：改为文档 URI 导入/导出或受控 DataShare/Want 接口，等核心功能稳定后再做。
- `BroadcastReceiver`/开机广播：改为 HarmonyOS 支持的系统事件/后台能力，并先做权限验证；不把 Android 广播名映射成无效 API。
- Quick Settings Tile、Tasker：暂不纳入首期，改用桌面快捷方式/通知操作/公开 Want（如果目标设备能力允许）。
- Android 前台 Service、`SharedPreferences` 明文秘密、直接执行 Android ELF：不移植。

## 七、验证与验收标准

### 自动/构建验证

- 纯 ArkTS 逻辑为 `FrpConfigManager`、文件名校验、重名、原子保存、备份路径校验和 TOML 验证增加测试；如工程测试能力允许，使用 `entry/src/ohosTest` + Hypium，否则把纯逻辑抽成可独立验证的函数并在构建流程中执行。
- 执行现有 Hvigor `assembleHap`，确认 OpenVPN 原有 native target 和 FRP target 都成功。
- 检查 HAP 内容只包含目标 ABI 的 FRP host/核心和必需依赖，无 Android-only `libfrpc.so` 假二进制。
- 检查动态库导出入口和依赖，确认没有把 OpenSSL 动态依赖漏进 HAP。

### 真机功能验收

1. FRP 与 OpenVPN 在首页一级切换，两个列表/状态互不串扰。
2. 导入 `.toml`、新建模板、创建空白配置、编辑保存、复制、重命名、导出、删除全部可用。
3. 空配置/错误 TOML/非法文件名/重名/保存失败均有可理解提示且不破坏原配置。
4. 单个 FRP 启停状态准确，正常退出/异常退出/服务重建后不会显示残留 Running。
5. 至少两个配置可并行运行，单个停止不影响其他实例或 OpenVPN。
6. 日志实时追加、历史恢复、清除和复制可用；敏感内容不进入 hilog 和通知。
7. 屏幕关闭、应用退后台、从最近任务清除、网络断开/恢复、系统回收 Ability 后，按 HarmonyOS 实际后台策略显示准确结果；不能把平台不保证的能力包装成永久保活。
8. 覆盖四种共存顺序：FRP 先启动/VPN 后启动、VPN 先启动/FRP 后启动、停止 VPN 保留 FRP、停止 FRP 保留 VPN，并验证 FRP 控制连接和本地代理流量是否按预期经过或绕过 VPN。
9. 目标 arm64 真机上完成版本探测、TLS、token、相对证书路径、TCP/UDP 代理和配置错误场景；x86_64 只有在依赖齐全后才宣称支持。

## 八、实施顺序

1. **平台闸门**：完成 Native Child Process 最小 host smoke test，确认签名 HAP、网络、fd、PID、kill 和退出回调。
2. **核心闸门**：锁定 FRP upstream revision，完成 OHOS 构建/host 适配，跑版本、配置解析、启停和双实例 smoke test。
3. **领域层**：实现配置目录、索引、模板、验证、日志、备份和安全路径处理，并补纯逻辑测试。
4. **独立服务层**：实现 `FrpServiceAbility`、状态快照、命令协议、并行实例和生命周期清理。
5. **UI 层**：加入首页一级切换、列表卡片、FAB、新建/导入/编辑/日志/导出页面，严格复用现有主题和组件。
6. **联调回归**：完成 FRP/OpenVPN 共存、后台、异常退出和真实服务器测试，修复后再宣称 FRP 功能完成。

这样实现后，FRP 在产品层面与 OpenVPN 同级，在代码层面与 VPN native/TUN 链路隔离，在配置层面比 Android 参考项目增加了空白新建、复制、原子保存、验证和更安全的生命周期处理。
