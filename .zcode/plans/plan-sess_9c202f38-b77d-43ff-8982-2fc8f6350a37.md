## 目标
对齐 `Index.ets` 中 OpenVPN 与 FRP 的顶部菜单栏：
- OpenVPN 仅保留一个“+”入口和“关于”，移除顶部“流量统计”和“日志”。
- FRP 将当前“新建配置”和“导入 TOML”两个顶部入口合并为一个“+”入口。
- FRP 的“+”入口弹出一个选择对话框，让用户选择“导入已有 TOML”或“新建配置”，分别复用现有导入流程和 `FrpTemplateDialog`。

## 实施步骤
1. 新增 `entry/src/main/ets/components/dialogs/FrpEntryDialog.ets`：
   - 复用 `ImportSourceDialog` 的卡片式选择交互实现“导入已有 TOML”和“新建配置”两个选项。
   - 选项整体可点击并有选中态；未选择时禁用“继续”。
   - 对话框关闭后通过回调通知宿主，不在组件内直接执行文件选择或路由。
   - 使用现有主题和图标资源，不新增或重命名 SVG。
2. 修改 `entry/src/main/ets/pages/Index.ets`：
   - 引入 `FrpEntryDialog` 并增加 `CustomDialogController`。
   - 增加 `showFrpEntry()`，选择“导入”时调用现有 `importFrpConfig()`，选择“新建”时调用现有 `showFrpTemplates()`。
   - OpenVPN 工具栏删除 `ic_chart`、`ic_receipt` 及其点击路由，将导入图标改为 `ic_add`，点击行为仍调用 `showImportChoices()`。
   - FRP 工具栏删除并列的 `ic_add`/`ic_import`，替换为一个 `ic_add`，点击打开 `FrpEntryDialog`。
   - 保持 `activeFeature`、标签切换、`ProfilesTab`/`FrpTab` 回调绑定以及现有导入/新建业务逻辑不变。
3. 不改动 FRP 空状态中的“导入 TOML”和“新建配置”按钮；本次范围只针对顶部菜单栏，避免扩大 UI 变更。
4. 验证：
   - 运行 `node entry/src/test/vpn-logs.cjs`。
   - 按 README 中的 Hvigor 命令构建 debug HAP，确认 ArkTS 对话框和资源引用通过编译。
   - 静态检查顶部两个分支：OpenVPN/FRP 各只保留一个 `ic_add`；OpenVPN 顶部不再出现统计/日志路由；FRP `+` 的两个选项分别仍到达原有导入和新建流程。

预期改动文件：`Index.ets` 与新增 `FrpEntryDialog.ets`；不修改现有 SVG 资源。
