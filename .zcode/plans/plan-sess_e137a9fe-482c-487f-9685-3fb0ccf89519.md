## 目标与术语
将“OPT Code”按常见含义实现为 **OTP（One-Time Password，一次性验证码）**。采用 OpenVPN/Access Server 标准 challenge-response 协议，不把验证码直接拼接到普通密码，也不把 OTP、challenge cookie 或 session token 保存到 Profile JSON。

实现分为两条链路：
1. Access Server/URL 导入时遇到 CRV1 challenge，输入 OTP 后重试下载。
2. VPN 隧道连接时支持 `static-challenge`、OpenVPN3 `DYNAMIC_CHALLENGE/CRV1`、`CR_TEXT` 和 `AUTH_PENDING` 的交互。

不引入 OpenVPN management socket：当前嵌入式 OpenVPN3 ClientAPI 明确拒绝 management 配置，项目中的 OMI 也没有编译进当前 native 库；直接桥接现有 ClientAPI 更安全、改动更小。

## 实现步骤

### 1. 建立一次性认证请求状态
新增 `entry/src/main/ets/core/AuthChallenge.ets`，定义连接/导入共用的短生命周期状态：requestId、profileUuid、source、kind、challengeText、echo、responseRequired、expiresAt、state。OTP response、CRV1 cookie、state ID、普通密码和 auth-token 仅保存在当前任务的内存或短期跨进程桥接文件中，提交/取消/超时/连接结束后立即清理。复用现有 `InputDialog`，补充统一二次验证文案和入口。

### 2. 先打通 Access Server 导入 OTP
修改 `ImportASDialog.ets`：HTTP 401 时解析响应中的 CRV1 challenge，兼容 `<Message>CRV1:R,E:<state>:<base64-user>:<challenge></Message>`；根据 flags 控制输入回显，弹出 OTP 输入框；按 `CRV1::<state_id>::<response>` 重试原 URL；限制重试次数，处理取消、超时和再次 401；成功后继续 `ConfigConverter`。OTP 不写 GP、Profile 或日志。

### 3. 扩展 OpenVPN3 native/NAPI 认证参数
修改 `index.d.ts`、`ovpn_napi.cpp`、`OvpnEngine.ets`：
- `OvpnStartOptions` 增加 `response`、`dynamicChallengeCookie`、`ssoMethods`、`info`。
- native 设置 `config.info=true`、`config.ssoMethods="webauth,crtext"`。
- 初始 `ProvideCreds` 传递 username、password、response、dynamicChallengeCookie。
- native 使用 `parse_dynamic_challenge()` 产出结构化 challenge 字段。
- 增加 `evalConfig`、`respondCrText`/`postControlMessage` 入口，支持 static challenge 元数据和 CR_TEXT 回传。
- 改善 client/worker ownership，避免 OTP 重试期间裸指针竞态。

### 4. 接通 static challenge
在 `ConfigParser`/`VpnProfile` 中保留 static challenge prompt/echo 元数据；连接前检测 static challenge，显示 OTP 输入，再把普通密码和 response 分开传给 native，由 OpenVPN3 Core 生成标准 SCRV1。实际 OTP 不持久化。

### 5. 接通 dynamic CRV1、CR_TEXT、AUTH_PENDING
`OvpnEngine` 专门处理 DYNAMIC_CHALLENGE、INFO/CR_TEXT、AUTH_PENDING、SESSION_EXPIRED，并屏蔽敏感 cookie；用户提交 dynamic response 后通过 pending request 以原配置+cookie+response 重新启动连接；CR_TEXT 使用 native `CR_RESPONSE`；AUTH_PENDING 解析 timeout 并展示等待状态。修正 WAIT/RECONNECTING/GET_CONFIG 状态映射。

### 6. 统一 UI 和后台启动
让 Profile 列表、快捷方式、日志页和 VPN Extension 启动使用同一套 transient challenge request：缺少凭据或 OTP 时保存待处理 UUID/reason，拉起/唤醒 EntryAbility 或通知；用户提交后自动继续连接；取消/失败/超时清理状态。

### 7. 安全清理
移除 `CMakeLists.txt` 中生产构建的 `OPENVPN_SHOW_SESSION_TOKEN`；DYNAMIC_CHALLENGE 原始 cookie、CR_TEXT response、OTP、密码和 auth-token 不进入 `VpnStatus` 日志、快照、Profile JSON 或 GP。

### 8. 双语资源和验证
补充二次验证、OTP、challenge、超时、失败和“不保存验证码”中英文资源。执行 Hvigor HAP 构建、native 构建、CRV1/static challenge 解析脚本、导入重试模拟和敏感字段静态检查；最后做普通密码、代理、快捷方式、高级设置和删除流程回归。
